## Q1 你们做的目的

**成稿素材**（可直接用）：

平台由学生自主开发、免费、无商业目的，解决两个实际问题：

1. **沟通不沉淀**：HKMU 学生日常信息分散在各种临时微信群，新生找不到、毕业带走、搜不到。平台提供围绕学校话题的公开讨论区（课程、校园生活、失物招领、二手信息），内容可搜索、可沉淀、可传承。
2. **选课规划难**：官方课程信息分散在多份 PDF 和网页里，学生很难弄清「自己离毕业还差什么」。平台把 55 个专业的官方毕业规则结构化，提供四年选课规划工具，全部数据对照官方 advice sheet 逐条核验。

【待定】是否加一句「希望未来能在学校指导下长期持续运营」——建议加，这是主任最想听的方向。

- 【待确认】同校邮箱验证目前是否强制（当时规划过 P0 同校邮箱，落地状态要核实后再答）。

## Q3 用户隐私保密协议

- 《隐私政策》《用户协议》《举报与反馈》文档已上线（平台内可查）
- 数据收集范围：微信 openid / 昵称头像（用户授权）、邮箱、课程规划数据；**不收**身份证 / 手机号 / 位置

## Q5 运行后台架构

**自主搭建**（不是套壳第三方平台）：

- 后端：FastAPI（Python），自主开发，版本管理 GitHub + CI 自动测试
- 前端：微信小程序 + 网页版（PWA）双端
- 服务器：Azure（东南亚）；数据库：Supabase（PostgreSQL）
- 域名已 ICP 备案，内容审核按微信官方要求全量接入

⚠️ **敏感预案**：学生数据存境外（东南亚/日本机房）大概率被问。如实说明 + 表态「如学校有要求，可评估迁移到学校认可的数据位置」。别当场承诺迁移工作量。

## Q6 后续发展规划 + 是否需要资金支持

- **短期（本学期）**：选课季服务 + 订阅消息召回 + 匿名课评（正用问卷验证需求）+ 双端功能对齐
- **中期**：iOS 版（技术评估已完成）、课表工具（问卷验证中）
- **资金**：运营成本极低（服务器约 US$15/月，可自付），**不缺资金**。
- **建议要的支持优先级**：官方渠道/信任背书 > 法务复核 > 新生触达渠道（迎新场景）> 资金。
  ——对现阶段来说，一条迎新渠道比一笔钱值钱得多。

【待定】Apple 开发者年费（约 ¥800/年）之类小额是否顺口提——可提可不提。

## Q7 发展阻碍 / 需要支持的部分

1. **非官方身份的信任缺口**——学生「不敢发、不敢信」，是冷启动第一障碍（背书本身直接解决）
2. **新生触达渠道**——往年只有靠个人分享，触达不了新生
3. **法务复核**——用户协议需要专业把关
4. **内容治理协同**——平台已合规运营，愿配合学校建立监督机制

**收尾要时间线**：如果 2 周内背书能落地，正好赶上选课季——请主任给一个明确的流程和时间预期。
