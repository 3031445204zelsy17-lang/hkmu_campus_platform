# 开学问卷设计(2026-09)

> 目标:55 人用户群 + 朋友圈分发,预期回收 30-50 份
> 工具:腾讯问卷(微信内原生打开,匿名,支持逻辑跳转)
> 每题对应一个正在做的优化决策,无废题

## 优化目标 → 题目映射

| 要优化的问题(现状) | 题号 | 拿到答案后干什么 |
|---|---|---|
| 激活率 4%,290 沉默用户 | Q1、Q3 | 沉默原因决定召回文案怎么写 |
| 周同比活跃下滑 / 微信群惯性 | Q4 | 知道竞品在哪,才知道差异化打哪 |
| 开学战役内容铺什么 | Q2、Q5 | 直接定内容排期 |
| 分享卡下一步做哪个方向 | Q6 | 定「晒规划」还是「新生攻略」优先 |
| 社区冷启动(UGC 飞轮) | Q7 | 障碍诊断定引导策略;「发过,以后也会发」= 种子发帖人池,重点运营 |
| 课评供给(核心壁垒内容) | Q8 | 匿名顾虑勾选多→上匿名课评;「没找到课」勾选多→查课程覆盖;「写过,以后也会写」= 种子课评人 |
| 口碑基线 | Q9 | NPS,以后每季度复测 |

## 设计说明

1. **Q1 是分流锚点**:腾讯问卷设逻辑跳转(从未用过 → 跳过 Q3/Q4/Q7/Q8/Q9/Q11)。朋友圈进来的非用户变成"获客调研样本"——Q3b 直接决定落地页第一句话写什么。
2. **Q3 选项是数据结论的翻译**:"内容少看着冷清"对应 Kimi 定的冷启动信任危机,"微信群惯性"对应真实竞品——沉默用户勾哪个,召回文案就打哪个。
3. **Q10 放了 AI 问答和独立 APP**:搁置 ≠ 否决,让它们做需求验证——进前三则 10 月排上,没人选就彻底放心。
4. **Q7、Q8 用障碍诊断代替「乐意发帖/课评吗」意愿题**:意愿题有严重社会期许偏差(都说愿意但不做);选项化障碍才能指导动作,单选逼选"最主要的卡点"。Q8 单拆课评,因为它的障碍独有:匿名顾虑(→匿名课评功能)、找不到课(→查课程覆盖)。
5. **Q12 微信号单独一题收集**,与答题数据物理分离(解 Kimi 报告点名的匿名性矛盾)。

## 合规要点(来自 Kimi 报告已识别的坑)

- 开头语含:匿名 + 用途 + 保存期限(建议 6 个月后删除)+ 联系方式
- 不打 HKMU 官方名义、不用校徽
- 红包小额、规则在群里公开
- 不强制任何个人信息

## 分发计划

| 渠道 | 动作 | 预期 |
|---|---|---|
| 用户群(55人) | 开学周晚上 9-10 点发,文案按"帮我们决定下一步做什么"写,抽 3 人红包 | 20-30 份 |
| 朋友圈 | 配文钩子 =「做完这份问卷,直接决定这学期给你做什么功能」+ 链接/二维码 | 10-20 份 |

**正式群发前**:先把链接发到文件传输助手,自己在微信里走完整填写流程,检查手机端排版 + 逻辑跳转是否生效。
