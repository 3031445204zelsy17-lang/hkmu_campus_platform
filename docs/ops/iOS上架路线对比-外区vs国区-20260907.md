## 1. 旧方案结论回顾(2026-07-31,仍然有效)

- 🥇 **技术栈:RN + Expo**——JS 逻辑复用 70-80%、supabase-js 同 SDK、EAS 云构建免 Mac、Android 同码、Apple 审核无歧视。
- ❌ Capacitor(4.2 套壳墙)、SwiftUI(0 复用无 Android)、Flutter(Dart 不复用)。
- 当时挂起的两个待定项:**① 栈** ② 上架范围**——本文档收口第 ② 项。

## 2. 上架标准核实(2026-09-07)

### 国区(硬门槛全齐才可提审)
| 要求 | 说明 |
|---|---|
| APP 备案号(工信部 105 号文) | App Store Connect 必填,App 名称/元数据须与备案一致;周期 ~30-40 天 |
| 服务器境内 | 备案经境内云商代办,主体/服务器/域名一致;海外后端办不了 |
| iOS 26 SDK | 2026-04 起强制(全球统一) |
| PIPL 数据合规 | 大陆用户数据境内;跨境回传境外 Supabase = 合规风险(PIPL 38 条) |
| 个人主体 + UGC | 政策灰区;微信侧已有个人+全功能 UGC 过审的实践反证(2026-08-03),App Store 国区未实测 |

### 外区(港/美等)
| 要求 | 说明 |
|---|---|
| Apple Developer $99/年 | 个人账号免 DUNS |
| iOS 26 SDK | 同上 |
| 隐私政策(5.1.1) | App 内 + App Store Connect 两处可访问 |
| App Privacy 隐私标签 | 如实填写数据类型/用途;有跟踪则加 ATT |
| **UGC 五件套(1.2)** | ①内容过滤 ②举报+响应 ③拉黑 ④公布联系方式 ⑤年龄分级 |
| Sign in with Apple(4.8) | 仅当同时提供其他第三方登录(Google/微信)时必须;纯邮箱登录不触发 |
| 4.2 功能完整 / 4.3 Spam | 通用条款;4.3 是全店第一大拒因(≈28%) |

## 3. 三条路线定义

| 路线 | 内容 | 前置 |
|---|---|---|
| **A. TestFlight 先行** | 开发完 → TestFlight 内测(种子用户/香港同学),不上店 | $99 账号 + Beta 审核(松) |
| **B. 外区正式上架** | 港区(可选+美区等)App Store 公开下载 | $99 + UGC 五件套补齐 + 隐私标签 |
| **C. 国区正式上架** | 中国大陆 App Store | B 全部 + APP 备案 + 境内服务器 + 主体(个人灰区/个体户) + 双部署分轨 |

**推荐组合:A → B 连续走(同一套产物),C 挂起等阶段 2(企业主体)。**

## 4. 路线对比矩阵

| 维度 | A. TestFlight | B. 外区正式 | C. 国区正式 |
|---|---|---|---|
| 行政门槛 | 无 | 无 | 备案 30-40 天 + 主体审查 |
| 架构改动 | 零迁移 | 零迁移(Azure SEA + Supabase 现状) | **双部署分轨**(2 后端 + 2 DB) |
| 金钱/年 | $99 | $99 | $99 + 境内服务器月费 + 可能软著 |
| 触达用户 | ≤1 万人内测 | **香港本地/国际生(主力,直接命中)** | 内地生(**已被小程序覆盖**) |
| 用户获取方式 | 邀请链接/邮箱 | 商店搜索/分享 | 商店 |
| 审核不确定性 | Beta 审核(低) | 首审 2-7 天(长尾 3-4 周) | Apple 审核 + 备案 + 运营期复查双层 |
| 后续运营负担 | build 90 天过期需续 | 常规版本更新 | 常规 + 备案周年 + 政策变动敏感 |

## 5. 工程复杂度评估(RN + Expo,外区路线)

### 5.1 后端(全部为外区上架前置,国区则再叠加双部署)
| 任务 | 复杂度 | 说明 |
|---|---|---|
| FR1c 内容审核断层补齐 | **中** | 现状:审核走微信 imgSecCheck 仅覆盖微信登录用户,邮箱/Google 用户 UGC 裸奔;iOS 端用户恰以邮箱登录为主 → 本地词库 + 第三方内容安全(阿里云/易盾/天御)fail-closed |
| 用户拉黑 API | 低 | 一张表 + 2 个端点(拉黑/取拉黑列表)+ 内容流过滤接入 |
| 官方联系方式 | 零 | 占位邮箱换官方邮箱(UGC 1.2 第④项,挂账 P0) |
| APNs 推送 token + 通知触发 | 中 | expo-notifications 对接,后端存 token 表,评论/私信触发离线推送 |
| Sign in with Apple 验签(若启用) | 低-中 | 仅当保留 Google 登录才必须;expo-apple-authentication + 后端验 JWT |

### 5.2 App 端(RN 重写 UI,逻辑复用)
| 模块 | 复杂度 | 说明 |
|---|---|---|
| 工程骨架 | 低 | Expo Router + 导航 + 主题 + 三语 i18n(JSON 可直接复用现有翻译) |
| 登录/注册/JWT | 低 | 复用现有 auth API;外区砍微信登录(用户群无微信)反而简化 |
| 资讯流/社区/帖子详情/发布器 | 中 | 列表-详情-发布三件套 ×4 个域(帖子/失物/新闻/课评);发布器含图片上传(Supabase Storage 复用) |
| 私信 | 中 | 轮询 3s 增量方案逻辑可搬(web/小程序已验证);RN 无 wx.connectSocket 坑,可试真 WS |
| **选课 Planner** | **高(全 App 最大件)** | 级联专业选择器(107 专业)+ 三语言搜索折叠(searchFold 逻辑可搬)+ 学分池计算 + 55 专业毕业规则;交互最重 |
| 个人资料/设置/协议页 | 低 | 静态为主,协议文本复用 2026-09-06 修订版 |
| 商店材料 | 低 | 隐私标签、截图、审核备注(测试账号!微信侧 4.5 教训) |

### 5.3 复杂度总量判断
- **前端页面 ~16-18 个**:低 6 / 中 8 / 高 1-2(planner 独占大头)。
- 逻辑层(API 封装/业务模型/i18n)复用 ~70-80%,**UI 全部 RN 重写**(不能搬 HTML/CSS,这是 RN 方案的唯一硬代价)。
- 无支付、无实时音视频、无原生复杂模块(推送是唯一原生面,Expo 托管)⇒ **整体中等复杂度,单人 15-20h/周可扛**。

## 6. 稳定度评估

| 层面 | A/B 外区路线 | C 国区路线 |
|---|---|---|
| **架构** | 单后端 = 现有 prod 稳定体系(已跑正式版小程序流量,镜像部署/CI/告警全成熟);App 只是新增客户端,后端风险增量小 | 双部署 = 双倍故障面:两套部署/监控/告警,数据一致性边界(内地生数据不出境),Supabase 海外+境内 DB 双轨维护 |
| **审核波动** | 首审 2-7 天,长尾 3-4 周(4.3 Spam 为最大变数);过审后更新审核 1-2 天,节奏可控 | 同左 + 备案流程 30-40 天 + Apple 侧对国区 App 的备案一致性复查;微信侧已示范过"运营期复查/被举报下架"模式 |
| **运营/政策** | Apple 政策全球稳定;UGC 五件套补齐后可持续,风险集中在内容治理本身 | 工信部政策变动敏感;备案周年/复查;数据跨境红线不可试探 |
| **依赖第三方** | EAS 免费额度 15 builds/月(超了 $19/月,量级无虞);Supabase/Azure 现有依赖不变 | + 境内云商(备案绑定)、内容安全厂商(境内版) |

**结论:外区路线稳定度 = 现有体系 + 审核一次性波动;国区路线 = 结构性双倍运维 + 政策敞口。**

## 7. 开发周期(15-20h/周假设)

| 阶段 | 内容 | 时长 | 备注 |
|---|---|---|---|
| 0. 增长假设验证 | PWA 用户构成/留存数据 + 访谈几个香港同学 | **~1 周** | 零成本,可跳过但不建议 |
| 1. 后端前置合规 | FR1c 审核断层 + 拉黑 + 联系方式(+推送 token 表) | **1-1.5 周** | 可与阶段 2 并行 |
| 2. RN 骨架 + 登录 + 核心三件套 | 工程搭建/导航/i18n/登录/资讯流/社区/详情/发布器 | **2-3 周** | |
| 3. 全量页面 + 推送 | 私信 + planner(最大件)+ 失物/新闻/资料 + APNs | **2-3 周** | planner 是关键路径 |
| 4. TestFlight 内测(A) | 种子用户 + 修反馈 | **1 周 +** | **0→A 合计 ~5-8 周** |
| 5. 外区提审(B) | 隐私标签/截图/测试账号 + 首审 2-7 天(备 3-4 周长尾) | **0.5-3 周** | **0→B 合计 ~6-10 周** |
| 6. 国区(C,阶段 2) | 双部署改造 3-5 周 + 备案 30-40 天(并行)+ 主体办理 + 提审 | **~3-4 个月** | 且依赖企业/个体户主体,不建议现在启动 |

> 对照旧方案"RN+Expo 5-8 周提审":本次细化后 0→TestFlight 5-8 周、0→外区正式 6-10 周,一致(旧数字未含后端 FR1c 前置,本版更保守)。

### 7.1 vibe 模式修正(纯 AI 主写,人只拆任务+验收)

按团队 vibe-coding SOP(CC 主写 + 人审),瓶颈从"写码速度"变为"验收带宽 + 外部时钟",周期压缩 ~2.5-3 倍:

| 阶段 | 常规(15-20h/周) | vibe·现实档(每天 2-4h 验收) | vibe·全职档(每天 6-8h) |
|---|---|---|---|
| 0 假设验证 | ~1 周 | 1-2 天(拉数据 AI 干,访谈仍需本人) | 1 天 |
| 1 后端合规 | 1-1.5 周 | 1-2 天(现成模式套用,pytest 门禁兜底) | 1 天 |
| 2 RN 骨架+登录+核心三件套 | 2-3 周 | 3-4 天 | 2 天 |
| 3 全量页面+推送(planner 大头) | 2-3 周 | 4-6 天 | 3-4 天 |
| 4 TestFlight 内测修反馈 | 1 周+ | 2-3 天(装机/走查是人工节奏) | 2 天 |
| 5 材料+首审 | 0.5-3 周 | 半天 + 审核 2-7 天(外部时钟) | 同左 |
| **合计 0→TestFlight** | ~5-8 周 | **~2-3 周** | **~1.5-2 周** |
| **合计 0→外区过审** | ~6-10 周 | **~3-4.5 周** | **~2.5-3 周** |

**vibe 模式四个真实瓶颈(周期表压不掉)**:
1. **验收带宽 = 人的时间**。AI 一天能吐完全部 16 页,但审不过来;"一个 prompt 一件事 + 人审"的 SOP 本身按人的带宽设计,全职档与现实档差距几乎全在每天可投入小时数。
2. **RN 是新栈,但坑由 AI 扛**。对 vibe 友好(人不用先学 RN);代价是排坑来回吃时间,尤其 expo-notifications 首次接 EAS 构建。
3. **planner 是唯一 vibe 加速有限的件**。页面可一天吐完,但 107 专业级联 + 三语搜索折叠 + 学分池的交互调优(动画/边界/简繁)仍靠真机走查迭代,按 4-6 天估,别指望 1 天。
4. **测试自动化决定上限**。RN 侧等价于 miniprogram-automator 的配方 = Expo web 预览快速走查(秒级热更新)+ Codex build-ios-apps 模拟器视觉验证;不搭,真机来回会吃掉省下的时间。

⇒ **纯 vibe 全职:0→外区过审 ~3 周封顶(其中 Apple 审核 2-7 天);现实档(课业之余):~3-4.5 周。后端 FR1c 无论 iOS 做不做都值得先做(现存风险,零依赖)。**
