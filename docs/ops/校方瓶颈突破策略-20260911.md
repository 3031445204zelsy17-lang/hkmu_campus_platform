# 校方瓶颈突破策略(ALTO / ITO 沟通路线)

> 2026-09-11 · 背景:SAO 创业赞助堵死;ALTO/ITO 态度未知;科技学院与两部门关系复杂,无自然沟通通道
> 配套阅读:总体日程路线图(产品线节奏)/ 司徒架构文档(技术交付物)/ 隐私合规路线图(安审弹药)

## 一、先看清瓶颈的本质

卡住我们的不是「对方意愿不强」,而是:**校园社区 App 这个问题,在学校里目前没有一个部门为它负责**——没有预算科目、没有责任归属、没有 KPI。我们在推一个解决方案,但组织里找不到那个「痛点持有人」。这是所有学生项目进校的通用死结,不是产品的问题。

因此「意愿强不强」这个问题**坐着想不出答案,连对方自己此刻都不知道**——答案只存在于三场低成本的谈话里。本策略就是这三场谈话的路线图。

## 二、干系人真实立场

| 干系人 | 它的 KPI / 职能 | 我们产品在它眼里的身份 | 正确用法 |
|--------|----------------|----------------------|----------|
| 招生会主任 | 招生宣传 | 已给过指路(找科技学院) | **要宣传 + 要人名**,不要他游说 |
| 科技学院教授 | 教学科研 | 已认可 AI 功能 | 引荐一个人名 / 陪同出席一次会谈 |
| ALTO | 交付便利学生的小项目 | 可能是省活的方案、撞车的货、或无关——取决于它有没有被需求咬过 | 请教式摸底,不带「卖」字 |
| ITO | 网络安全、数据安全、IT 基建稳定 | 潜在影子系统,本能是风险规避 | **只审不买**;等有可审实体再进 |

## 三、三步走顺序(核心策略)

```
第 1 步 主任(关系最热)  → 要一波学生宣传 + 要一个人名      ← 本周即做,零成本
第 2 步 ALTO(摸底)     → 30 分钟「请教式」会谈            ← 有人名就去,目标=搞清情况
第 3 步 ITO(流程)      → 等可审实体成型再进                ← T2 交接包+具体部署方案就绪时
```

**为什么 ITO 必须最后碰**:安审部门对未成形东西的条件反射是拒绝。现在带着「想卖给学校」去找它,它没有可审的实体(部署在哪?数据流?谁维护?),只能回「学生项目不方便支持」——这个「不」一旦出口,将来要花双倍力气翻转。**宁可晚,不可早。**

## 四、每一步具体要做什么

### 第 1 步:找主任要两样东西(两个请求分开提)

1. **宣传**:「能不能通过招生/新生渠道帮我们推一下这个 App?」——这是他的本职领域,零预算零风险,张口就来。**与 ALTO/ITO 线完全解耦**:用户量涨了,将来跟任何部门谈筹码都厚一分;就算全卖不动,宣传本身也不亏。
2. **人名**:「如果想去 ALTO 或 ITO 请教一下,您觉得找谁比较合适?」——只要名字和一句引荐,不要他上门游说(跨部门游说要动用他的人情和背书风险,会消耗这段关系)。

### 第 2 步:ALTO 摸底(目标不是成交,是搞清四件事)

1. ALTO 明年的项目路线图里,有没有和课程规划/社区/校园服务撞车的项?
2. 它接手学生项目有没有先例?流程是什么样?
3. 它对接手外部项目最大的顾虑是什么?(经验上十有八九是「学生毕业了谁维护」)
4. 它和 ITO 打交道的实际路径是什么?

谈话姿态:「我们做了个东西学生在用,想请教一下如果做成学校正式的服务,应该怎么走、需要什么。」——通篇不提卖字。

### 第 3 步:ITO 进场条件(满足即谈)

- T2 交接包成型(镜像+部署模板+运维手册)
- 具体的部署方案书(数据在哪、账号谁的、AI 安全)
- 有 ALTO 侧或学院侧的人引路
- 满足以上三条之前,任何 ITO 接触都暂缓

## 五、摸底后的信号判读表

| 对方反应 | 信号含义 | 我们的下一步 |
|----------|----------|--------------|
| 问用户量、问维护、问交接 | 真兴趣 | 两周内给交接包节选 |
| 「我们已有类似/已在规划」 | 撞车 | 转向移交/共建,不硬卖 |
| 「这个得 ITO 说了算」 | ALTO 无痛感,推给守门人 | 重心转 ITO 流程摸底(第 3 步提前) |
| 「学生毕业怎么办」 | 最大真实顾虑 | 交接包+文档+可选维护期承诺作答 |
| 全程客气、无具体问题 | 无痛感 | 止损回产品线,攒筹码等选课季数据 |

## 六、手里的牌(弹药清单)

**已在造的**(产品线,不受瓶颈影响):iOS 双端 App(B1-B8 → A1-A11)+ MU Agent —— 这就是「ALTO 可以直接接走的产品」。

**已备好的**:
- 「数据不出校」部署架构(专为 ITO 安审设计:跑在学校租户、师生用学校账号、AI 用学校额度)
- 交接三件套的设计(镜像/模板/手册)
- 司徒的架构+隐私文档(已补第三至五部分)、白话版、合规路线图

**待备的**:交接包实体(11 月节点)/ 署名机制(App 关于页+商店+LICENSE)/ **底牌决定:授权(保留著作权+署名,倾向此项)还是买断(署名写进合同当底线)**——接触 ALTO 谈实质前必须想清。

## 七、时间轴与止损线

| 时点 | 动作 |
|------|------|
| 本周 | 主任两个请求(宣传+人名) |
| 拿到人名即约 | ALTO 30 分钟摸底 |
| 10 月中前 | 完成 ALTO 摸底;产品 10 月底成型,正好可演示 |
| 若 ALTO 无痛感 | 止损:回产品线,选课季攒用户数据,12 月窗口再评估;期间主任宣传持续做 |
| ITO 接触 | 严格等三条件满足(见第四节) |

## 八、三条原则(谈判期间不破)

1. **署名是前提**,不因任何 offer 让步;倾向授权而非买断
2. **不逼主任游说、不提前碰 ITO、不因谈判中断开发**——产品线(B1 起)照常推进,每一步都让可出售资产变厚
3. 所有校方动作成本控制在「一次谈话」级别,不做超出当前关系的请求
