# 小程序接手开发指引(司徒 · Windows)

> 目标:在你自己电脑上打开项目、改代码、模拟器实时看、真机预览、提交代码——和 SYF 屏幕上一样的效果。
> 全程约 30 分钟搭建,之后每天开发只需要第 3 节的循环。

---

## 0. 前置(SYF 先做,做完才轮到你)

- [ ] MP 后台 → 成员管理 → 项目成员 → 把司徒加为**开发者**
  (没有这步,你打开项目会提示 AppID 无权限,登录功能也会坏——必须先做)
- [ ] GitHub 仓库 → Settings → Collaborators → 邀请司徒的 GitHub 账号
  (你会收到邮件,点接受)

---

## 1. 一次性环境搭建

**Step 1 · 装微信开发者工具(Windows 64 稳定版)**

下载:https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
选「稳定版 Stable Build · Windows 64」,一路默认安装。

**Step 2 · 装 GitHub Desktop**

下载:https://desktop.github.com
装完打开 → Sign in to GitHub.com → 登录你的 GitHub 账号(浏览器里授权一次)。

**Step 3 · 把代码拉下来**

GitHub Desktop → File → Clone a repository → 选 hkmu-campus-platform →
Local path 填 **`C:\dev\hkmu-campus-platform`**(纯英文路径,别放中文目录)→ Clone。

**Step 4 · 导入小程序项目**

打开微信开发者工具 → 项目列表页「导入」→ 目录选:
`C:\dev\hkmu-campus-platform\miniprogram`
AppID 会从 `project.config.json` 自动读到,**不要改**。

> ⚠️ **必须选 `miniprogram` 子目录,不是仓库根目录!**
> 判断标准:选完后文件列表最上层能看到 `app.json`、`pages/`、`app.js`。
> 如果选成 `C:\dev\hkmu-campus-platform`(根目录,里面有 docs/frontend/backend),
> 模拟器会报 `app.json is not found in the project root directory`。
> 已经选错的补救:项目列表 → 该项目右键 → 删除项目(**弹窗里不要勾"删除项目文件"**)→ 重新导入正确的目录。

**Step 5 · 登录**

工具右上角头像 → 扫码登录你自己的微信。

**✅ 验收标准:**

模拟器出现首页,底部五个 tab(首页/校园/消息/选课规划/我的)都能切,
资讯页能看到真实帖子——说明已连上生产后端,环境就绪。

## 2. 权限边界(先知道,免得卡住)

| 操作 | 你 | SYF |
|---|---|---|
| 改代码 / 模拟器 / 真机预览 | ✅ | ✅ |
| 「上传」生成开发版本 | ✅ | ✅ |
| 设体验版 / 提审 / 正式发布 | ❌ | ✅(管理员) |

发布闸门在 SYF 手里是刻意的:你随便开发,上线节奏他控制。

## 3. 每日开发循环(背下来)

```
① 开工先拉最新:GitHub Desktop → 点 Fetch origin → 有更新就 Pull origin
② 要做新功能:Branch → New branch → 命名 feature/模块-描述
③ 改代码:开发者工具里改,保存自动编译,模拟器直接看
④ 真机看:工具栏「预览」→ 手机微信扫码(手机和电脑都要联网,不用同一 WiFi)
⑤ 提交:GitHub Desktop → 勾选改动文件 → commit 标题写 [模块] feat: 描述 → Push origin
⑥ 完成后:在 GitHub 上提 Pull Request → 群里喊 SYF review
```

**commit 格式**(项目约定):`[模块名] feat/fix: 一句话描述`,例如:
`[community] feat: 帖子卡片圆角调整`

---

## 4. ⚠️ 数据安全(最重要的一节)

**模拟器和真机预览连的都是生产环境(真实后端 + 真实数据库)。**

- 测试发帖/评论会进真实库,真实用户能看到
- 测试内容用测试账号:**testuser1 / B6test2026**,或发完自己删
- 你自己的微信号在平台是 admin,可以删任何帖
- **绝对不要**在生产库里灌批量测试数据、改用户资料

## 5. 常见问题

| 症状 | 解法 |
|---|---|
| 导入项目提示「AppID 无权限 / 不是本账号小程序」 | 项目成员没加,找 SYF(第 0 节) |
| 登录页一直报错、拿不到 openid | 多半用了「测试号」打开项目——关掉项目重新导入,用真实 AppID |
| 预览扫码后白屏 / 请求失败 | 看手机网络;设置里**别勾**「不校验合法域名」(域名已在白名单,不需要) |
| 改了代码模拟器没变化 | 工具栏「清缓存 → 清除全部缓存」→ 重新编译 |
| Push 被拒 / PR 冲突 | 十有八九是没拉最新:Fetch origin → Pull origin → 在自己分支上解决冲突 |
| 模拟器连不上后端(全部请求失败) | 罕见;确认没有改动 `utils/` 里的 API 地址配置 |

---

## 6. 协作规矩(项目既有约定,一起守)

1. **分支保护**:所有改动走 feature 分支 + PR,不直推 main
2. **模块归属**:你名下的模块(首页、宣传、UI、测试)自由发挥;
   动到 SYF 的模块(选课/私信/认证等 `pages/` 对应目录)在 PR 里说明
3. **小步提交**:做完一个小点就 commit,别攒一大坨
4. **卡住就问**:环境问题 30 分钟没解决,直接找 SYF,别自己耗

---

*环境搭好后,把第 3 节的循环跑一遍:开个分支改个字 → 预览 → commit → PR,全链路通了就算正式接手。*
