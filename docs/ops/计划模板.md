## 前提清单(必填,v1.1 六列 — 查什么/什么算过/证据哪来,缺一即仪式)
| # | 前提假设 | 查什么(命令) | 通过标准 | 证据来源 | 结果 |
|---|---------|-------------|---------|---------|------|
| 1 | 例:账号有免费额度 | az account subscription show | 类型含 Student **且** 额度>0 | CLI 当次实时输出 | ✅ |
| 2 | | | | | |

**结果三态**:
- ✅ 通过 — 命令输出达到通过标准
- ❌ 不满足 — 前提确认不成立 → **停,等人裁决**
- ⚠️ 无法验证 — 网络/权限等工具原因 → 重试一次,仍败则**降级继续但必须记录**("验不了什么+因此自负什么风险")

> 穷尽前提不可能。**高风险前提(钱/数据/鉴权/不可逆)必验**,其余可标"未验证(原因)"。
> **全绿 ≠ 安全**——只等于"已知风险清零",清单外的风险照常存在。

## 使用纪律(v1.1)
1. **前提**:高风险必验 + 三态判定;❌不开工,⚠️记录后降级
2. **豁免挑刺的标准=影响面**:低影响×低成本×可逆**三者同时满足**才可免;凡触**鉴权/数据边界/费用/删除**的改动**永不豁免**——与代码行数无关(一行也能关掉鉴权)
3. **验收开工前写完**(写完代码才补的验收=先打靶后画靶心)
4. **过保鲜期的计划禁止开工**;跨天任务天天重验前提
5. 基建类:动云前后各跑一次 `python3 scripts/infra_audit.py`

## 错误暴露时限(本架构自身的验收标准,v1.1 新增)
| 错误类 | 允许多久被发现 | 靠什么兑现 |
|--------|--------------|-----------|
| 资源漂移(多了/少了) | ≤ 7 天 | 每周点货 |
| 成本超上限 | ≤ 1 个账单周期 | 点货成本栏 + 账单 |
| 前提失效 | ≤ 下次开工 | G2 门禁 |
| 代码缺陷 | ≤ CI | 测试门禁 |

> 不承诺"立刻暴露"——承诺的是**每类错误有时限、时限可核账**。
