## 五、管线根因(为什么会漏这么久)

1. **join 型管线只富化、不新增**:scrape_ge_catalog.py 按课码 join 已有 GE_COURSES,官方新课程永远进不来
2. **对账单向**:校验只查已 join 行的准确性,不查覆盖率 → 漏收静默通过,自测全绿
3. **seed 无学期数据时用课码首位当 year**(seed_courses.py `_level_year`),当时已知折衷,没人回头修
4. 生产 programmes_catalogue.has_full_planning 列过期(仅 DSAI=True;前端 planner.js:1138 有兜底,无用户可见影响,属数据洁癖)

**防复发原则:对账必须双向(缺失+多余),覆盖率断言进 CI(池数 ≥ 官方目录数,不过就红)。**

## 八、爬取配方备忘(Cloudflare)

- curl 任何指纹 = 403;无头 Playwright 也被识破
- 可靠配方:**有头 Chromium + ignoreDefaultArgs:['--enable-automation'] + --disable-blink-features=AutomationControlled**,过盾 15-30 秒;过盾后必须再 goto 一次稳定页面
- 取 PDF 用**页内 fetch**(同源同 TLS 同 cookie)→ base64 回传落盘;Playwright 的 ctx.request API 走 Node TLS 会被 CF 拒
- 630KB 大文件要 90 秒+超时;官方服务器对部分文件限速,并发无用
- 每份 Yr 表只含**当前学期**(8 月发秋季版,春季版约 12 月),换季要重爬
